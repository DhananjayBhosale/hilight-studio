## Changes for 1.0.13 (version code 14)

- Root recovery now tolerates a departed helper's PID being reused by an unrelated process, without
  signaling that process. A different surviving helper still blocks recovery. AUTO can retry a
  recovered root destination only after exact source exit and before ADB cleanup has started.
- Setup has an optional Shizuku-loss notification. It remembers an actually working transport,
  stays off by default, requires notification permission, and avoids warnings during a working
  connection or active root startup. An intentional disconnect clears the remembered connection.
  The notification opens Setup and is excluded from HiLight's notification rules/reminders.
- An opted-in, previously connected Shizuku user gets a one-time delayed availability check after
  reboot. The receiver/job do not initialize Store, request root permission, or start a renderer.
- Seven patterns from @saboooor's PR #39 were adapted into the existing preview and device
  renderers: Meter, Strobe, Heartbeat, Bounce, Radar, Converge and Glitch. Existing duty, brightness,
  duration and cleanup limits remain. Renderer revision 8 forces replacement of older helpers.
- Compilation is explicitly pinned to Android 37.0, matching F-Droid's existing recipe even when
  Android 37.1 is installed locally. Package identity and release certificate remain unchanged.

## Verification and review boundaries

- The full unit/build/lint gate passed with 337 tests, no failures or errors. Lint has zero errors;
  the eight additional warnings recommend SharedPreferences KTX syntax rather than flagging a
  correctness defect. Standalone helper compilation is separate from the APK build.
- New shell-fixture tests execute the real stop command against private fake process records.
  They verify exact TERM, unrelated PID reuse, different-instance rejection, another helper,
  and empty/unreadable identity. No host or phone process is signaled by those tests.
- Pattern tests compare preview/device frames at multiple speeds, brightness levels and times,
  verify saved-look round trips, and check dark rests, meter fill, bounce and convergence symmetry.
- Manager-loss tests include a failed/fenced Shizuku state with a dead manager; a live binder or
  active connection attempt does not count as manager loss.
- A completed Gemini 3.8 Flash source-fragment review prompted tighter root-start warning gating.
  Other findings were checked against full source: errors become ERROR/DENIED rather than an
  automatic retry loop, root priority is existing behavior, and stop commands already compare
  exact instance tokens. The proposed boot-receiver export change was rejected: Android explicitly
  permits system broadcasts to an unexported receiver ([official receiver documentation](https://developer.android.com/guide/topics/manifest/receiver-element)).
  Grok could not review because its account was out of usage. Neither route supplies device evidence.
- The connected Pixel was absent; a separate API 37.1 emulator was created for this release's
  installation and UI/boot-notification checks. It cannot verify LED hardware or Magisk/KernelSU.

The signed 1.0.12 to 1.0.13 emulator upgrade preserved all 16 preference entries from the prior QA
fixture (including rules, presets, schedule settings and the disabled master switch), with no
uninstall or data clearing. Publication, final checksums and boot-notification results follow below. The Play variant is handled in the existing PlayStore Release task,
keeping its application ID, feature restrictions and Play in-app updater.
